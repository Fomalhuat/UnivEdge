## 1. 需求澄清（来自 han）

- **领域背景**：数值相对论，求解引力自力（gravitational self-force）。
- **两条工作线**：
  1. **形式化推导**：扰动方程、主方程等的符号推导（已有 xAct skill 支撑 Mathematica 计算）；
  2. **数值计算**：占比很大，涉及大量数值工具链。
- **定位**：**科研助手**——暂时不需要自主完成整个科研流程；底层逻辑是"懂科研流程的 agent"，在物理上特化。
- **痛点**：大模型**手算（形式化推导）经常出错** → 需要"设计工具"或"设计审查流程"提升正确率；数值方面也要表现好。

## 2. 蓝图的变与不变

### 2.1 不变的部分（v1 结论仍成立）

- 五层 harness 架构；三层验证思想；linter/纪律强制；知识层作为记录系统（渐进式披露）；专家（han）在环作为最终裁判。

### 2.2 修订一：L1 工作流层——从"自主研究循环"到"科研上下文感知的子任务服务循环"

v1 把"物理方法循环"当作 agent 自主运行的脚本。但助手定位下，**循环不是脚本，而是坐标**：

- agent 维护一份**科研上下文地图**（research context map）：当前项目进展到哪个阶段、每个子任务属于方法循环的哪个环节（提出/建模/推导/计算/检验/结论）；
- 人类下达子任务 → agent 定位上下文 → 选择工具链 → 执行 → 验证 → 返回**可审计结果 + 下一步建议**；
- 人类负责判断与决策（掌舵），agent 负责执行与质量把关。

这正好对齐 OpenAI harness 文章的核心："人类掌舵，智能体执行"。

### 2.3 修订二：验证重心——从"数据检验为主"到"符号推导 + 数值 双主线"

对应 han 的两条工作线：

| 验证主线             | 针对场景            | 手段                                      |
| ---------------- | --------------- | --------------------------------------- |
| **符号推导验证**       | 扰动方程、规范变换、自力表达式 | 结构检查 + 物理检查 + 数值特例验证（详见 §4）             |
| **数值验证**         | 积分器、通量、模式求和、收敛性 | 收敛性 + 守恒残差 + 解析极限 + benchmark 复现（详见 §5） |
| 基准检验（原"数据检验"的落点） | 与文献已知结果对比       | self-force 的 benchmark 表就是"数据"          |

### 2.4 修订三：确立"工具代算"原则（针对手算出错的核心对策）

**LLM 永不手算作为最终产物。** 推导由符号计算引擎（xAct/Mathematica/SymPy）执行；LLM 的角色是：规划推导路线 → 编写工具代码 → 解释结果。这比"审查大模型的推导文本"可靠得多——审查对象从"可疑文本"变成"可执行、可复现、可审计的工具代码"。

## 4. 符号推导可靠性管线（核心新组件）

```
LLM 起草方案 → 工具执行（xAct 代算）→ 结构检查 → 物理检查 → 基准数值验证 → 人工复核 → 产出
     ▲                                                                    │
     └──────────── 不通过 → 携检查报告回退（≤ MAX_ITER） ←────────────────┘
```

**各环节检查项（self-force 语境）：**

1. **结构检查**（机械可查）：编译通过；自由指标平衡；张量类型/阶数正确；缩并正确；对称/反对称性；Bianchi 恒等式。
2. **物理检查**（物理不变量）：量纲/单位（G=c=1）；极限情形——$M\to0$ 平直时空、$a\to0$ Schwarzschild 极限、圆轨道极限、静态度规极限；**规范不变量**（Regge–Wheeler/Zerilli 与 Teukolsky 变量的不变性）。
3. **基准数值验证**：把推导结果在特殊情形数值化，与文献已知结果对比（如 Detweiler 红移不变量、Barack–Sago 的 Schwarzschild 圆轨道自力数据、与 PN/EOB 展开的比对）。
4. **人工复核**：han 作为领域专家在关键节点把关。

**失败路径**：任意环节不通过 → 带着检查报告回退到起草，重新迭代，直到通过或达到 MAX_ITER。

> 这就是 OpenAI 文章"把品味写成 linter"在物理推导上的具体化：推导的"品味"（指标平衡、极限正确、规范不变）被编码成可执行检查与数值测试。

---

## 5. 数值正确性协议

- **收敛性测试**：网格/步长/模式数 $m$ 截断的收敛阶检验；
- **守恒残差**：能量/角动量通量平衡（辐射反应场景）；
- **解析极限对比**：弱场、零自旋、圆轨道等已知解析结果；
- **benchmark 复现**：复现文献表格数据（作为"单元测试"）；
- **可复现性**：固定版本与随机种子，输出记录；
- **误差传播**：自力的轨道演化误差预算。

## 6. L0 知识层新增（相对 v1）

- **约定注册表**：度规符号、$G=c=1$、规范选择、各论文的约定对照表（自力的文献里约定五花八门，这是幻觉重灾区）；
- **基准结果库（benchmark registry）**：文献已知结果表 → 数值验证的"单元测试集"；
- **文献主张注册表**：从 arXiv 抽取公式/结论并带溯源。
