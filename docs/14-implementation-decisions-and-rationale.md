## 1. 判断依据：三类判准（按顺序适用）

1. **是不是"接一条已生效规则的门"？**
   - 若是 → **做**。已生效的规则若无可核判据，按 §0.2 元原则只能 `claimed`；
     **接门 = 让已批准的规则真正生效**（例：D —— `§3.4.1 #6` 早已生效，而 R2 未附探针，属规则悬空）。
2. **是不是"为空结构建门"？**
   - 若是 → **缓做**，等真实用例。理由：**先有真实用例、再有机制**——
     无用例的门无从校准，且极易变成"配置好了但从不触发"的假绿
     （例：E1 —— `§3.4.1 #8` 要求分类，但目前**没有任何产物声明白己的类别**）。
3. **是不是"用户已明确不加"的类型？**
   - 若是 → **不做**，且**不默认推翻**（要推翻须显式重裁）。
     （例：E4/E5 与"批次 2 不加门"直接冲突 → 已请示，用户维持原决定。）

> **到期条件（本节补记，2026-10-13，依 docs/13 Q4c）**：本判准集本身属**判断类**，按 `§0.2②` 须带到期——
> **20 次审查或 60 天（先到者）后复核**：若其间未出现"判准误用导致误缓/误做"的实例，判准继续有效；
> 若出现，则修订判准并留痕（修订不覆盖原文）。
>
> 三类判准的次序有意义：**先看是否接已生效规则（该做）** → **再看是否空结构（该等）** → **最后看是否用户已否（不做）**。
> 若次序颠倒，会把"接已生效规则"误判成"加门"而搁置（D 即是此类）。

## 2. 我特意**没有**做的两件事

1. **没有把 C 做成"自动派生计数"**（尽管 `docs/12` R2、`docs/13` C 都这么建议）：
   实测在真实核验表上**漏计 83%**（6 份表 → 1 条，而其中一份表自述"S0×2 成立、S1×5 全部成立"）；
   根因是**核验表格式不统一**（S0 用 `## S0-N` 小节 + `✅`；S1/S2 用汇总表格 + "认可"表述）。
   **自动判定的失效方向是危险的**：漏计 = 假阴性 = 把"仍在发现真问题"的工作类型误判为"零发现"
   → 触发**错误毕业** → 此后**漏审**。故降级为"**只保证不漏条、不代为判定**"（判定留给生成者）。
2. **没有为 `docs/12` / `docs/13` 保留索引例外**：两者入库后，`AGENTS.md` 索引统一为 **01–13**；
   若保留"某文档暂不列入"的说明，该说明本身就会变成新的"索引与实际不符"。
