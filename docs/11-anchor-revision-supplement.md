3. **§4.4 的 A1 定位**（同源实例只能作发现器、不得作判据）——判断正确且重要。**补一句措辞**：

   **把 R7 从"需求来源"改为"线索来源"**——线索须经 A2 复现（可复现命令 / 构造性检验）才成为需求。

### 2.2 建议补充两条

**补充一：A2 应显式包含"构造性检验"（探针 / 受控实验）。**

提案的 A0–A3 分级没有给"探针检验"落位。它既不是 A3（不是外部现实/文献值），
也不是 A1（不是同源 LLM 实例的又一次运行）——但它是**独立于生成者声称、且可复现**的。

> 建议：**探针 / 受控实验 = A2**。判据是"能否造出一份**应当被抓**的数据，并观察它是否报错"。

**依据（本会话实例）**：第十二轮修复"计数检查的解析面"时，正是靠构造性检验挖出真缺陷——
改现行契约的 `116/116` → `115/115`，检查**仍报"全部通过"**（假绿），遂定位到正则对契约 0 命中。
若只读代码或只跑常规测试（全绿），该缺陷不会暴露。

**含义（直接回答"没有外部锚点怎么办"）**：**锚的本质是"独立于声称的检验通道"，不是"数值参照"。**
构造性检验给出的正是这种通道——它可复现、可反驳、且不依赖作者自述。

**补充二：§8 点 2 的阈值应加一条"扫描面约束"。**

从病例看（提案 §3.2 表：计数一致性检查 2 天 5 改），危害最大的不是行数，而是**新增 / 扩大扫描面**——
5 次改动全部围绕"扫什么"（README → 契约 → 收窄 → 解析面 → DRY）。

> 建议：**新增或扩大扫描面一律上缴**（哪怕 ≤ 20 行且不新增文件）。

## 4. 关于"是否撤回既有修改"（用户 2026-10-12 提问）

**结论：不做批量撤回；按"事实类保留 / 判断类定向复核"分流处置。**

### 4.1 事实类修复不应撤回（提案附录 B 中 7 项）

白名单 `isUserAuthored`、测试日志隔离、契约补交、扫描面收窄 + 历史留档、解析面修复、
DRY 计数面 + 位置检测器、递归 `find` + 证据新鲜度迁移——它们修的是**客观缺陷**
（`agent-instructions` 被当人发文本致任务描述错配、正则对契约 0 命中、日志硬编码不可隔离…）。
**撤回等于把已确认的缺陷放回。**

### 4.2 判断类动作不宜立即撤回（5 项）

1. **撤回本身是一次大动作**（改代码 + 测试 + 证据 + 基线），**会再触发一轮"修复"**——正是要避免的；
2. 门与探针常同体，删除会留下**孤儿断言**（提案 §4.3 已指出）；
3. 其价值判据（命中 / 误报 / 代价）**只能在运行中取得**，而装置 2026-10-12 12:34 才上线。

### 4.3 正确处置 = 加验证条件，而非撤回

对每个判断类机制补**三问记录**：**① 抓到过真问题吗（命中）② 误报过吗（假红）③ 维护代价（改动次数）**；
观察窗口 = **上线后 20 次审查**；窗口内无命中 → **降级休眠**（保留判据与探针、退出交付门、复发即续期）。

**已知数据（本会话）**：计数一致性检查 2 天 5 改（高维护），但**抓到过真漂移**
（README 93 vs 94；第十轮"升级为一致性比对后当场抓到 3 处新的漂移"）→
属"**高代价但确有命中**"，**不宜直接撤**，宜先降门槛观测。

### 4.4 若裁决要求收缩，建议顺序

先降级"无命中且高维护"者；最后才考虑删除；**删除必须同时登记其测试 / 探针 / 基线的处置**（防孤儿断言）。
