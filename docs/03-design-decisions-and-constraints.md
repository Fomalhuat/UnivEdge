## 1. 定位修正：通用物理科研助手

- han 明确：引力自力只是说明"物理研究有各种问题"，符号推导与数值计算是**两类贯穿所有物理子领域的能力**；
- 因此：任务分类法、验证协议、方法论规范全部按**物理通用**设计；领域知识（self-force、GR、等离子体、凝聚态……）作为**可插拔内容**进入知识层/技能层，而非硬编码进工作流；
- 考核口径也相应变化：agent 应能在任意物理子领域内完成 符号推导 / 数值计算（含复现）/ 文献核对 三类核心子任务。

---

## 2. 决策一：工具/技能注册表（Tool & Skill Registry）

han 的核心表述：**"xAct 和 SymPy 都是工具，应该在合适的时候使用它们；有时需要自己开发工具或总结 skill。"**

由此确定 L2 层的设计：

- **工具一律平等**：xAct/Mathematica、SymPy、自研脚本、既有库——都是注册表里的条目，由"任务类型 → 工具"路由规则动态选择（符号推导 → 符号引擎；数值 → 执行环境；文献 → 检索/解析）；
- **技能 = 方法论 + 工具的知识包**：如 han 已有的 xAct skill。harness 内置**技能提炼工作流**：当 agent 反复成功解决某类问题后，把"问题特征 → 工具 → 步骤 → 验证"沉淀为可复用技能，进入技能库；
- **工具缺失 → 自研**：允许 agent 开发新工具（写代码/包装既有库），先通过验证再注册成为一等公民；
- 对应架构：L2 从"固定工具列表"升级为 **注册表 + 路由 + 技能库 + 自研工作流**。

---

## 3. 决策二：多语言/远程执行环境

han 的澄清：科研代码异构——C++ 有限元、Python 作图分析、乃至 HPC 集群；agent 完全可能去**复现某篇文章的数值方法**（此前已在另一个工作目录实践过）。

- **本地沙箱多语言执行**：Python / C++ / Fortran / Julia 等，统一执行接口；
- **远程 HPC 驱动**：ssh + SLURM/sbatch（PRD77 案例就是 sbatch 编译运行链）；
- **"复现文献数值方法"正式入列任务分类法**：读论文方法 → 重实现 → 运行 → 对照文献结果（表格/图/量级）→ 收敛与误差报告；
- 工具链差异（编译器、节点类型、并行库）写入 config/ 与适配层，不污染方法论核心。

---

## 4. 决策三：可移植性（不绑定目录、不绑定平台）

han：需要一个**可移植的 agent**，不绑定当前工作目录、不绑定 WorkBuddy。

- agent 本体 = 一个自包含、版本化、环境无关的**项目仓库**，可整体迁移到任何环境（独立 CLI、其他 agent 平台、服务器）；
- 平台差异全部外置到 config/ 与工具适配层；
- 项目结构（草案）：

```
physics-agent/
├── AGENTS.md          # 地图：~100 行目录，指向深层文档（渐进式披露）
├── docs/              # 设计 / 方法论规格 / 验证协议（01/02/03…）
├── knowledge/         # 约定注册表 · 基准结果库 · 主张注册表 · 文献库
├── skills/            # 可移植技能包（含 xAct 技能等）
├── tools/             # 自研工具 + 执行环境适配层（本地沙箱 / 远程 HPC）
├── config/            # 环境无关配置（HPC 参数、沙箱约束外置）
└── run/               # 产物存储（可插拔，宿主提供——审计产物，可重建，不入版本库）
```

## 5. 决策四：锚点原则（做一步检查一步）

han：**"我们必须做一步检查一步，保证每一步都没错（科研总是要从正确的锚点出发）。"**

这既是**本项目的工作方法**，也是**agent 的运行时原则**：

- 对项目本身：每步产出的文档（本系列 01/02/03…）由 han 复核后，才作为下一步的锚点；
- 对 agent 运行时：任何产物必须锚定到**独立可验证的参照**——已知极限、守恒律、文献基准、已复核的上游结果；
- 状态机强化：**未锚定的结果只能是 claimed，不能进入结论**。锚点缺失时，agent 的义务是"请求锚点"，而不是直接给出结论。

## 6. 实证锚点：PRD77 有效源复现案例（来自 2026-08-10 工作目录）

背景：agent 复现 PRD77 有效源（FEM 代码，C++，HPC/SLURM），三判据误差从 2.77%/1.05%/0.38% 压至 0.012%/0.019%/0.002%，与导师参考逐位一致。

**提炼出的"复现类任务验证协议"要素（直接进入 Step 3 验证协议）：**

| 要素 | 案例中的具体做法 | 协议化要点 |
|---|---|---|
| 锚点对照表 | 判据/复现值/参考值/误差 四列 | 固定报告模板：每个数值产物必附对照表 |
| 误差通道分解 | 力=dφ（网格细化）、场=φ（静态初始化）、∂_t=虚部（宽网格） | 误差按物理通道分而治之，禁止盲调参数 |
| 最小改动对照实验 | `verify/analyze_h005_compare.py` 单一变量对比 | 一次只改一个因素，证明因果 |
| 收敛阶检验 | 发现"只改演化 h 不改源表 h"的误导（源表采样二阶收敛） | 收敛性必须覆盖管线的**每一环节** |
| 环境可复现 | 编译参数/节点/OpenMP 写入 `build_kerr2026a.sh` | 环境是结果的一部分，必须文档化 |
| 运行链文档化 | 表生成→静态初始化→演化→mode-sum 串行依赖 | 管线依赖图明确，可断点续跑 |

> 这个案例证明：通用 agent + 正确过程已经能完成高精度复现；harness 的职责是**把这种"偶然的优秀过程"变成可重复的规范**。

## 7. 任务分类法（v3 更新）

| 任务类型 | 示例 | 工具（动态路由） | 验证 |
|---|---|---|---|
| 符号推导 | 扰动方程、主方程、规范变换 | 符号引擎（xAct/Mathematica/SymPy…） | 推导可靠性管线（02 §4） |
| 数值计算/复现 | 复现文献方法、自写计算、作图分析 | 多语言环境 + 远程 HPC | 复现验证协议（§6） |
| 文献核对 | 公式抽取、约定/规范/单位对照 | 检索/文档解析 | 溯源 + 一致性检查 |
| 验证审查 | 对以上产物独立挑错 | 独立于生成者 | 解耦（DeepMath 原则） |
| 工具/技能开发 | 自研工具、提炼技能包 | 代码 + 文档 | 注册前先过验证 |
