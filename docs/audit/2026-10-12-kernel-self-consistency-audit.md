## 3. 共同根因（本次审计最重要的发现）

**F1–F5 的结构完全相同**：

| 内核自己声明的约束 | 守它的判据 |
|---|---|
| 计数/数字须一致 | ✅ run-tests.sh 计数检查 |
| L1 义务不得消失 | ✅ l1-invariants（149 断言） |
| 判据必须会响 | ✅ 负控门 |
| 证据不得过期 | ✅ L1 基线 H 组 |
| **版本号须与变更史一致** | ❌ **无** |
| **目录索引须与实际一致** | ❌ **无** |
| **内核不得含项目语境** | ❌ **无** |
| **零硬编码** | ❌ **无** |

→ **内核的"文档级约束"全部处于"无判据守护"状态**，因此会随时间**系统性漂移**——
这不是疏忽，而是**结构性的**：我们给"装置"加了很多门，却从未给"内核文档自身的约束"加过门。

**这与内核刚写入的元原则（2026-10-12）完全同构**：

> "任何规则/检查/门，若不能被一个**会响、且取自真实运行路径**的判据证明有效，则只能 **claimed** 且**默认带到期**。"

→ **"不依赖具体使用者语境"这条定位，至今没有判据** → 它一直处于 **claimed** 状态且**从未被检验** → 所以泄漏了。
（同理：版本一致性、零硬编码。）
