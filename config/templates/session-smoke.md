# 会话启动冒烟（承接性任务）

> 依据：METHODOLOGY §1.1（v0.15）/ docs/16 B1-1 / docs/20 W5
> 用途：**新会话接手既有产物**时，动手前先确认工作区未处于 broken 状态。非承接性任务（从零开始）可跳过。

## 三步（5 分钟内）

1. **找到"上一状态"**
   - [ ] 最近一次运行的产物目录（`run/<task>/`）与报告（`report.md` / `verification_summary` 等）；
   - [ ] 最近一次审查结论（`run/review/INDEX.md` 或审查报告）；
   - [ ] 当前任务契约（若有）与其中的"完成定义 / 硬阈值"。
2. **跑最小可执行检查**（选与任务最相关的一条，不要全量）
   - [ ] 数值类：跑一次最小规模用例（如 1 档网格/1 个 mode），与已知结果比对；
   - [ ] 代码类：跑最小测试或 `--help` / 单模块导入；
   - [ ] 文档类：校验关键 JSON/YAML 可解析、引用路径存在（如 `verify_refs.py`）。
3. **记录结论**（写进本次报告顶部，三行以内）
   - [ ] `冒烟：通过 / 失败（原因）/ 跳过（非承接性任务）`
   - [ ] 若失败：**先修，不开新工作**；修复本身作为本次任务的第一个交付单元。

## 反例（必须避免）

- 直接在上次结论上继续推导，未确认上次产物是否完整；
- 把"文件存在"当作"状态完好"（必须实际执行一次最小检查）；
- 冒烟失败后绕开问题继续（会污染后续所有结论）。
