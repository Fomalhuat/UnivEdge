# 复核教训库（Review Lessons）

> 记录系统：把踩坑沉淀为**线性独立的根因基**，而非无限增长的具体清单。
> 设计原则（元思想，本库的最高原则）：**领域内核固化的是从具体例子中抽象出的规律，不是例子本身**——
> 像高明的人类学习者：不背错题，而从错误提炼根本原因，从而避免一类错误。
> 具体教训是无限集，根因基是有限集——错误类型构成一个集合，内核只保留其**线性独立的一组基**。

## 基层：五个线性独立的根因方向（AI 的任务内省清单）

**B1 无依据断言**：我是否在产出缺乏真实依据的结论（捏造公式/数值/引用）？——未锚定的结论只能 claimed；LLM 永不手算作为最终产物。
**B2 语义歧义**：影响数值解读的自由度（符号约定、单位制、坐标/规范、截断阶数、归一化、相位）是否显式声明并对齐？——若两个研究者按此定义会算出不同数值，则该自由度未声明。
**B3 工具/方法误用**：当前工具/算法是否在其有效域内运行？库的默认约定是否与标准一致（转置、相位、索引）？——边界处显式测试；约定不确定时数值交叉验证为权威，解析只做锚点。
**B4 验证失效（meta 层）**：验证/测试设计本身是否可能有盲区，导致漏过 B1–B3？——"测过了"不等于"测对了"；因素拆全、判据可判定、锚定独立参照。
**P 流程执行（gate 前置，与 B1-B4 正交）**：我是否**跳过必须的前置动作就直接动手**（未建立配置基线就改参数、未加载协议就执行、未完整复刻生产链就"最小改动"、未读生产配置文档就提交作业）？——流程类错误**教训库救不了，只有门控能拦**：副作用前 / 结论前 / 交付前三处强制自省（见 §1.2 契约"启动自省"）。

> 说明：B4 是拦截器（作用在 B1–B3 之上）；P 是**流程执行维**（B1-B4 是"怎么做错"的知识判断，
> P 是"根本没按流程做"的执行缺失）——两者正交，故并列。过程迷失是果非因，不单列。

## 例子层：按基展开（新教训先归类，无合适基才建新基）

### 基 B1：无依据断言

#### B1-1 推测被误标为"已确认"（V2 符号撤回）
- **日期**：2026-08-18（litcheck01 复核揭示）
- **教训**：标量自力符号"正号=物理实际"最初是 han 的**物理解释性推测**（反射机制），
  曾被标记为"已确认（han 确认）"。后 han 澄清：推测未经严格验证——正号的物理合理性
  不等于数值结果的符号正确性。**物理机制性解释 ≠ 验证**；凡未经独立数值对照/守恒判据
  检验的结论，状态只能 claimed，且须显式标注"推测"。
- **影响**：若直接按"符号已确认"推进演化任务，耗散通道 Ė 可能因符号错误而物理上荒谬
  （dE/dt > 0 能量增加），污染整个演化链。
- **沉淀**：conventions.md §2.2.2（V2 撤回为待验证，验证判据 dE/dt<0）；VERIFICATION
  NC-06（外部锚点）；产物状态机（claimed ≠ verified，须验证器/用户确认才升级）。
- **验证方法**：任何"确认"都要追问——依据是独立验证还是推测？推测必须标 claimed +
  给出可判定的验证判据。
- **后续（2026-08-19）**：V2 已通过独立验证（SymPy 代数 + PRD77 频域锚点 + r⁻⁴ 标度律），
  升级 verified——B1-1 的闭环：推测 → 撤回 → 独立验证 → 升级。验证方法被证明有效。
- **⚠️ 复发案例（2026-08-21，rewrite3d "近粒子污染"误判）**：3D 场 Re 系统性错误时，
  构造了"保守场对近粒子源结构敏感"的物理解释性叙事，在**未做直接检验**的情况下
  宣布"根因锁定"（剩余最可疑 → 直接宣布）。han 问"插值还是解析式"后，
  30 秒的决定性实验（粒子邻近点解析求值）推翻假说。**教训：教训库存在 ≠ 执行**；
  排除法只证明"这些不是"，不证明"剩下的是"；B1-1 的"追问"应升级为可执行清单
  （→ VERIFICATION RC-06 根因宣布协议，若采纳）。

#### B1-2 波区通量的慢瞬态污染（通量平衡法的隐含前提）
- **日期**：2026-08-19（v2symbol 通道 B）
- **教训**：用短时演化（T1600）的波区场做能量通量平衡，得到 dE/dt 虚高 ~12 倍。
  根因：波区场需"substantial number of orbits"才达螺旋稳态（PRD77 原文明确），
  短演化下粒子处 f 仍单调增长（慢瞬态）——**通量平衡的隐含前提 = 场已达稳态**，
  粒子处自力提取（∂_tψ^R）一个轨道即稳（PRD77），边界通量则需长得多。
- **沉淀**：conventions.md §2.2.2（波区通量需长演化）；VERIFICATION NC-02（收敛检验须
  覆盖"演化时长"这一维度，不能只看空间网格/截断）。
- **验证方法**：边界通量计算前先检查"粒子处场是否已稳态"（f(t) 尾部斜率），
  并做演化时长收敛扫描（T400/T800/T1600/T3200）。

### 基 B2：语义歧义

#### B2-1 同名物理量可能是不同对象（1/ρ 领头阶 vs 完整奇异场）
- **日期**：2026-08-13（Step 4C 测试揭示）
- **教训**：PRD67 的 1/ρ 可展开到四阶（O(ε²)），用户语境中"1/ρ"是标准记号（代入附录公式即得完整场）；agent 照字面执行领头阶，交付"字面正确但物理不充分"的量。
- **影响**：Φ_res 慢收敛（档差 l^−2），与用户收敛真值（−1.0498e-3）偏差 ~10%。
- **沉淀**：METHODOLOGY §1.2 物理量定义（判据式，建议性）+ 已知参照值（软性请求）。
- **验证方法**：任务开始先问"这个量在该语境下的标准定义是什么？有没有已知参照值？"

#### B2-2 球谐负 m 相位
- **日期**：2026-08-13（Step 4B/4C）
- **教训**：Ylm 负 m 实现漏 (−1)^m 相位，ΦS_{l,−m} 恢复规则错误（自洽但错）。
- **沉淀**：knowledge/conventions.md §1.1；VERIFICATION CC-01。
- **验证方法**：恒等式 Y_{l,−m}=(−1)^m Y*_{l,m}；实函数约束 a_{l,−m}=(−1)^m a*_{l,m}。

#### B2-3 文献表 vs 自身图不一致（PRD77）
- **日期**：2026-07/08（用户科研过程，docs/07 记录）
- **教训**：PRD77 Table 1 与论文自身图直和高 2.8%——印刷表可能错误。
- **影响**：一度误以为自身实现错误。
- **沉淀**：文献核对任务（METHODOLOGY §4）执行时参考；docs/07 建议"跨来源交叉验证"（暂未入内核，YAGNI）。
- **验证方法**：同一量在多个来源不一致时，显式标记并判断哪方更可信（优先数值锚点）。

### 基 B3：工具/方法误用

#### B3-1 sympy wigner_d 转置
- **日期**：2026-08-13（Step 4B）
- **教训**：sympy wigner_d 矩阵是标准小 d 矩阵的转置+相位差异，按"行=第一指标"读取会错误归零（l 奇 m 奇模）。
- **影响**：Wigner D 解析路径整体弃用，改双独立数值路线。
- **沉淀**：knowledge/conventions.md §1.2。
- **验证方法**：与标准 d 矩阵数值对照（如 d^1(π/2) 已知矩阵）；约定不确定时数值为权威。

#### B3-2 nquad 高 l 端点奇点
- **日期**：2026-08-13（Step 4B）
- **教训**：1/√(1−cosΘ) 端点奇点在 nquad 直积下高 l（l≥19）roundoff → NaN。
- **沉淀**：knowledge/conventions.md §1.3（u=1−cosΘ 变量替换）。
- **验证方法**：在边界参数（最高 l / 最小步长 / 奇点附近）显式测试；收敛扫描覆盖边界。

#### B3-3 上游/权威实现的内部近似（thz_c_lm 切平面内区）
- **日期**：2026-08-14（Step 4C-Full）
- **教训**：用户远程 C 实现 `thz_c_lm`（thz_source.hpp）是**验证过能复现 PRD77 结果**的权威代码，但其内区用切平面近似（θ=TH0+ψcosα，eps=0.15），在 r=r_p 处带 **~1.2e-5 系统误差**。整体流程精度 0.019% 不受影响（近似被大流程平均掉），但单独提取 c_lm 用于新任务（ret−singular 相减，Φ_res ~1e-3）时，1.2e-5 会污染 ~1%。
- **根因**："整体验证通过" ≠ "子组件精确"——上游实现的内部近似被继承到新任务的精度需求上。
- **影响**：若直接信任远程 C 输出，Φ_res 会带 ~1% 误差；通过 eps→0 收敛测试判定本地精确实现（1.2e-5→3.6e-9）。
- **沉淀**：VERIFICATION RC-04（交叉验证独立性）/ NC-06（外部锚点对照）——即使锚点是"已验证的权威实现"，也要做边界/收敛测试确认其精度有效域。
- **验证方法**：对继承的上游组件做**有效域边界测试**（本案例：积分内区参数 eps→0 收敛）；"已验证"只保证整体结果，不保证子组件精度。

### 基 B4：验证失效（meta 层）

#### B4-1 测试只测了部分因素（h 测试）
- **日期**：2026-08-13（docs/07，源自用户 2026-07/08 真实过程）
- **教训**：收敛测试"变化不大"实为只改演化步长、漏改源表采样——测试者以为测了一个因素，实际漏了耦合因素。
- **影响**：约 17 天无效循环；最后靠另一个 AI 重新研究才发现。
- **沉淀**：METHODOLOGY §5.5 测试设计审查；VERIFICATION RC-05。
- **验证方法**：最小改动对照——列出全部相关因素，逐一确认"这次只动了一个"。

#### B4-2 用错误标准验证自身（负 m 自洽假象）
- **日期**：2026-08-13（Step 4B/4C）
- **教训**：用同一个有 bug 的函数验证自身结论，全 PASS 但错——自洽 ≠ 正确。
- **沉淀**：VERIFICATION NC-06（外部锚点）、RC-04（交叉验证独立性）。
- **验证方法**：至少一处与独立实现/文献/用户数据对照，且交叉路线实现层独立。

#### B4-3 离散数据比较未插值到同一自变量（S_lm 假差异）
- **日期**：2026-08-19（rewrite3d 源验证）
- **教训**：比较 S_lm 表（r* 均匀网格 h=0.005）与逐点投影值（r=10 精确）时，脚本取
  "最近表节点"（r*=12.7750，距精确 r*=12.772589 偏差 0.0024）→ **假差异 0.19%**。
  根因：S_lm(r) 在粒子位置（r=10）附近**极陡**（~8%/0.01 r*），最近节点偏差被放大。
  线性插值到 r=10 后两边一致到 **0.0004%**——0.19% 完全是比较方法造成的虚惊。
- **影响**：若照 0.19% 误报去"修源"，会污染已正确的源；正确结论是源一致。
- **沉淀**：rewrite3d report §5.2（含插值修正说明）。
- **验证方法**：比较两个数据源前先检查函数陡峭度（斜率）；离散表必须**插值到同一自变量**
  而非取最近节点；可疑差异先做插值敏感性测试再下结论。

#### B4-4 跨代码复振幅比较必须实证标定（2π + 相位因子）
- **日期**：2026-08-20（rewrite3d 3D 耗散提取验证）
- **教训**：对比 3D 球谐投影 proj_lm 与 v1.0 序列拟合的 c_lm 复振幅时，手推相位还原公式
  得到"90° 相位差、幅度差 2π"的误判。实证标定（用 v1.0 已知场构造快照跑投影逻辑）揭示：
  project_lm 的 φ 求和是**平均**（Σ_k/np = ∫dφ/2π）→ proj = ψ_lm/(2π)·e^{−imΩT}，
  正确还原 ψ_lm = 2π·proj·e^{imΩT}（标定比值 0.1592 ≈ 1/2π 验证）。
- **根因**：工具内部隐含约定（φ 平均 = 1/2π）未显式记录；跨代码复振幅对比不能依赖手推，
  必须用已知场做端到端标定。
- **影响**：若按手推公式提取，∂tψ^R 相位错 90° → 耗散提取失败。
- **沉淀**：rewrite3d dEdt_verify.md §2.2；VERIFICATION NC-06（外部锚点）+ RC-04。
- **验证方法**：任何跨实现复振幅/相位对齐，先构造已知解析场跑目标管线做**端到端标定**，
  再应用到真实数据；手推只做 sanity check。

#### B4-5 比较前先统一提取口径（窗口/统计协议不一致 → 假差异）
- **日期**：2026-08-22（开放问题① 诊断，rewrite3d 遗留问题关闭）
- **教训**：比较"旧方程 vs 新方程"逐点源的 Im 偏差时，报告称"1.5%（旧）→ 14%（新）"，
  疑似新方程使耗散通道恶化。统一提取协议（同一干净窗口 [105,195]、同一复振幅还原
  ψ_lm = 2π·mean(proj·e^{imΩt})）后，**1.5% 是旧方程在长窗口 [402,800] 的偶然值，
  同一数据在干净窗口下偏差 20%**——新旧方程同量级（20% vs 14%），"新方程恶化"是假象。
  根因：ψ_11 复振幅存在窗口间波动（±5-15%，慢瞬态/未达螺旋稳态，投影源亦有），
  单窗口值有 ~10% 不确定性；不同窗口取值的比较产生虚假差异。
- **影响**：若照"新方程恶化"去修方程（PC-05 已证 3D 新方程与 v1.0 连续严格等价），
  会污染正确的方程；浪费 1 天以上的错误归因（本案例在 1 天内经口径统一排除）。
- **沉淀**：rewrite3d openq1_final.md（根因宣布 claimed）；与 B4-3（空间自变量口径）
  同族——**"比较口径"一般化：空间上插值到同一自变量，时间上统一提取窗口/统计协议**。
- **验证方法**：比较两个实现/两次运行前，先确认**提取协议完全一致**（窗口、拟合方法、
  相位/归一化、源注入方式），并做**窗口敏感性检查**（滑动窗口扫描，若窗口间波动超
  目标精度则需多周期平均或更长演化）；可疑差异先排除"口径"再归因物理。
- **关联**：B1-2（慢瞬态：场未达稳态是窗口波动的物理来源）；B4-3（同族）。

## 新增教训流程

1. **先归类**：判断属于哪个基（B1–B4 + P）→ 加入该基例子区；
2. **无合适基才建新基**：基的数量应缓慢增长（这是设计意图——基层必须保持短小）；
3. **建新基前先检验独立性**：新基是否可由已有基线性组合而成？若是（如"过程迷失"= 其他基未被拦截的后果），不建——错误类型集合只保留**线性独立的一组基**；
4. **同步沉淀**：每次新教训应关联到内核规则/检查项（METHODOLOGY / VERIFICATION / conventions），并回写对应文件。
